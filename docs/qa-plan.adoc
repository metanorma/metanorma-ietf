== Context

PR #257 rearchitects how `metanorma-ietf` generates RFC XML v3. It *deletes the
entire `IsoDoc::Ietf` layer* (22 files, Nokogiri/string-based) and the *11
`spec/isodoc/{asterisk}_spec.rb` files* (≈87 examples, ≈6,800 lines of
feature-by-feature tests), replacing them with a *model-driven `Transformer`*
built on `metanorma-document` + `rfcxml` + `lutaml-model`, tested only against
*two fixture documents* (`example` = RFC 1149; `antioch` = an Internet-Draft).

The PR was written by the project owner and handed to the maintainer to QA and
integrate. Four concrete objections drive this plan:

1. *No navigable overview* of the new architecture. (Addressed by
   xref:architecture.adoc[`architecture.adoc`].)
2. *Epic methods* — single methods of 50–187 lines.
3. *Discarded tests* — the feature-level `spec/isodoc/` suite was dropped for
   two whole-document fixtures; the diffs were called "minor" without evidence.
4. *Unverified output parity* — no systematic comparison of old vs new RFC XML.

Intended outcome: a trusted, readable, well-tested, well-documented transformer
producing correct RFC XML, with the maintainer's feature tests restored as the
regression safety net.

=== Agreed sequencing

Decided 2026-06-04, amended 2026-06-05:

*WS1 architecture doc → WS1b enrichment-architecture spike + build → WS2
old-vs-new comparison (two fixtures) → WS3 fold `spec/isodoc` tests back → WS4
refactor → WS5 `mn-samples-ietf` full-corpus QA.*

WS1b is the *central architectural decision* (see <<inherited-enrichment>>): the
new transformer drops the autonumbering/xref/reference-label/footnote enrichment
the old path inherited from `IsoDoc::Convert`, and we reinstate it as a
pared-down `PresentationXMLConvert` preprocessing stage. It runs *before* WS2 so
the comparison and re-folded tests measure the *intended* pipeline, not the PR's
stripped one. Comparison precedes test-folding to establish ground truth on the
"diffs are minor" claim early. Refactoring is gated on a green restored suite.
The `mn-samples-ietf` sweep runs last, on code that is both trusted and readable.

[[inherited-enrichment]]
== Key finding: inherited enrichment (corrected)

An early read mischaracterised the old `PresentationXMLConvert` usage as "purely
a helper." That was wrong. The old `IsoDoc::Ietf::RfcConvert < IsoDoc::Convert`
runs a *full enrichment pipeline* inherited from the base class: `Xref#parse`
(before `convert1`) computes section/note/example/figure/table/formula labels,
ordered-list values and footnote numbering; `document_preprocess` adds
`reference_names` (`[RFC2119]`-style labels) and requirement rendering. These
feed the RFC XML output.

The new transformer initialises `@xrefs = {}` and never populates it, so it
*drops or defers wholesale to xml2rfc* the xref/eref text, eref locality
formatting, figure/table/note numbering, formula labels, concept resolution and
annotations; footnotes are reimplemented but *restructured* into back-matter
endnotes. These are prime candidates for the "minor" discrepancies.

*RFC-specific nuance.* RFC XML legitimately defers section/figure/table
numbering and internal xref text to `xml2rfc` at render time (bare
`<xref target="..."/>`, no `<num>`). So we must *not* inject the full numbering
pipeline. The subset RFC XML needs *pre-resolved* is what xml2rfc won't compute:
reference labels, formula/note/example literal-text labels, eref localities.
This is the design basis for WS1b. Full detail in
xref:architecture.adoc#inherited-enrichment[`architecture.adoc`].

== xml2rfc nits (QA yardstick)

"Nits" is IETF jargon for the warnings/errors from the IETF's own tooling. Two
layers, both installed locally (`xml2rfc 3.25.0`, `idnits`):

* *xml2rfc* validates well-formedness + the RFC 7991 v3 schema and warns while
  rendering; `<?rfc strict="yes"?>` enforces I-D nits and DTD validity. Flags:
  `--warn-bare-unicode`, `--strict`, `-v`, `-s PREFIX`.
* *idnits* checks IETF *submission* requirements on the text output (boilerplate,
  reference categorisation, line length, …).

Both are distinct from the transformer's internal `validation_transformer`.

*Why it matters:* nits are an objective compliance yardstick. A difference is
not automatically a regression — if the new code emits *fewer* nits it is *more*
compliant. Nits feed triage two ways: as a comparison surface, and as the
*severity axis* (deltas that introduce/remove nits outrank cosmetic ones).

=== WS1b — Enrichment architecture: the overlap test (evidence-gated)

Goal: establish *by testing against real documents* which of the enrichments
the old path inherited from `IsoDoc::Convert` the new transformer (a) already
replicates, (b) drops with a functional consequence xml2rfc cannot recover, or
(c) correctly defers to xml2rfc — and only then decide whether any pared-down
presentation stage is warranted. Agreed with the PR author 2026-06-07:
*default is no presentation layer*; a pared-down stage returns only for
enrichment proven both dropped and xml2rfc-unrecoverable. The KEEP/SUPPRESS
table below is the *instrument* of that test (the hypothesis list to check),
not a pre-decided build list. *(This supersedes the earlier revision of this
section, which framed WS1b as a decided build.)*

|===
| Hypothesis | Passes
| *KEEP-candidates* | reference labels (`reference_names`), formula labels,
note/example literal-text labels, eref locality formatting (`eref_localities`),
footnote numbering/de-dup, requirement/recommendation/permission rendering
| *SUPPRESS (xml2rfc's job)* | section/figure/table numbering, internal xref

==== Interim reading (after run 1)

* *Scoped decision (maintainer, 2026-07-17): xref-integrity and
  reference-machinery work stays with the shared isodoc presentation
  machinery and will not be reimplemented in model space.* Grounds: N2 is an
  xml2rfc-fatal failure of exactly the anchor↔target coherence function that
  machinery provides, and N3 a partial reimplementation of its reference
  fallbacks; the shared code is mature, calibrated, and — being a core
  component of presentation-XML processing used by every flavour — *will
  continue to be maintained regardless of this PR*, so relying on it costs
  the IETF flavour nothing marginally. Re-deriving the same function inside
  the transformer both reproduces the failure mode under audit and creates a
  new, IETF-only maintenance liability for code no other flavour exercises.
  The pared preprocessing stage (below) therefore owns xrefs and
  reference enrichment; remaining KEEP-candidates stay subject to the
  overlap test as coverage completes.
* This decision does *not* absorb the pure input-mapping defects (N1, N4,
  N5, N7, N8, N10, N11): those are transformer-side fixes owed regardless of
  any presentation stage.
* One enrichment loss confirmed xml2rfc-unrecoverable so far: *note
  numbering* (N6).
* Every other fatal or major delta on this testbed is an input-mapping defect
  — the data exists in Semantic XML and is lost in model space (N1, N2, N3,
  N5, N8–N10). For those the open question is *design placement* (shared
  machinery vs per-transformer reimplementation), not raw capability; N3 and
  N9 are direct instances of the transformer partially reimplementing shared
  behaviour.
* The A-class findings feed the WS2 discrepancy log as fix tasks; run 1 also
  validates the WS2 harness shape (same-input dual-path, three diff
  surfaces) on a real corpus document.

(entire sourcecode corpus, formulas, user anchors, publisher-as-author,
and on antioch no output whatsoever). On current-schema inputs, zero of
three documents tested produce usable RFC XML through the new path.

[[ws1b-restructure]]
==== Programme restructure (2026-07-17)

The WS1b/WS2 evidence gates WS3: folding the `spec/isodoc` regression suite
back in against the transformer in its current state would enshrine
defective output as test expectations. A *repair programme* (WS-R: debug,
refactor, re-baseline fixtures against the current semantic schema) is
therefore a prerequisite for WS3, running alongside the QA workstreams. Its
opening backlog is the A-class findings above plus N12, N13 and F1.

*Build shape for the decided layer* (updated 2026-07-19): an
**extraction refactor, not new construction**. The selective use of the
shared presentation infrastructure that IETF needs — references, xrefs,
captions, a limited fmt-* exposure — is *already encoded* in the released
`lib/isodoc/ietf` code via its `IsoDoc::Convert` inheritance; the released
path has always run exactly this constrained subset implicitly. The work
is to extract that selection formally into a standalone presentation-XML
generator stage, emitting *enriched Metanorma XML* (so `from_xml` still
consumes it and the transformer is unchanged), wired into
`transformer.rb#convert_forward` and the processor `:rfc` path; the
transformer's redundant half-reimplementations are then removed or pointed
at the enriched input.

*Scope constraint (maintainer, 2026-07-21): the extracted stage is
deliberately thin.* It owns the xref machinery, the relaton-render
reference rendering — including the no-title/no-formattedref fallback
ported to the released path in `metanorma-ietf@81f7bc1` (#272), whose
in-code REFACTOR marker anticipates exactly this unification — and not
much else. The released `lib/isodoc/ietf` code, which already takes its
reference/xref logic from the isodoc presentation-XML converter, is the
*normative definition* of the subset: nothing goes into the extracted
stage that the released path does not already exercise.

*Architecture ruling (maintainer, 2026-07-22 23:47): the stage RUNS the
shared converter; it does not port its functions.* A first spike built
"enriched semantic XML" by porting `populate_id` and the formattedref
fallback into a bespoke enrich harness — rejected: two of its three
operations were second implementations, self-refuting for a layer whose
stated justification is DRY ("I cannot argue the layer is needed for
DRY and then reimplement it"). The build shape is therefore a genuine
`IsoDoc::Ietf::PresentationXMLConvert <
::IsoDoc::PresentationXMLConvert` subclass as the pipeline's first
stage — Semantic XML → pared presentation XML → `Root.from_xml` →
transformer → RFC XML — with:

* *most passes switched off* (the `conversions` fan-out —
  `metadata/bibdata/section/block/terms/inline` and their
  sub-passes — is overridable per method; the keep/kill list is decided
  by the WS1b overlap-test method, evidence per pass, not a priori);
* the *transformer taught* the presentation idioms it must read —
  under the governing criterion (maintainer, 2026-07-22 23:59): *a
  pass survives only if the transformer needs its decision, decisions
  are preferred in attribute form, and `fmt-*`/`semx` are consumed
  only where a needed decision has no other carrier*. Proven
  attribute-carried already: anchor→`id`, note/formula `autonum`.
  Suspected no-other-carrier case: reference rendering (maintainer's
  stated concern that avoidance may be impossible there); fallback
  that stays DRY: *invoke* the shared bibrenderer from the transform
  side with IETF configuration, as released `references.rb` does —
  calling shared code is not porting it;
* verified empirically (2026-07-22 probe, base PXC on fresh rfc-3339):
  the shared converter already does anchor→`id` promotion (17/17) and
  `autonum` stamping on notes — confirming both ported functions were
  redundant duplicates.

Survivors from the first spike: the *consumption-side* transformer
changes (reading `autonum` in preference to local counters —
`block_transformer.rb`) and the spec corpus; the enrich-harness
operations are superseded and slated for removal when the subclass
lands.
