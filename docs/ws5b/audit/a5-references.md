## Findings

1. **Hidden bibitems emitted (element_order branch).** (a) origin/main:lib/isodoc/ietf/references.rb `biblio_list`: `next if implicit_reference(b)` (`bib["hidden"] == "true"`). (b) New leg checks `hidden_bibitem?` only in the fallback branch (reference_transformer.rb:88); the `element_order` branch (line 77–78) — the branch actually taken on metanorma-document 0.2.9 — appends every bibitem unconditionally. (c) Input: `<references><bibitem id="HID1" hidden="true">…` — empirically run through `Metanorma::Ietf::Transformer.convert`: the hidden reference appears in `<back>` as a full `<reference anchor="HID1">`. Old leg omitted it. (d) Confidence: **high** (empirical).

2. **HTML-typed URI no longer becomes reference target.** (a) references.rb `ietf_bibitem`: `target = u.text if %w(src HTML).include?(u["type"])`. (b) reference_transformer.rb:372 `extract_bibitem_target` matches `type == "src"` only. (c) Input: `<bibitem><uri type="HTML">https://example.com/html-version</uri>…` — empirically confirmed: old emits `target=`, new emits no target. (d) Confidence: **high** that behavior differs; **medium** on real-world impact (relaton IETF records use `src`; HTML-typed uris occur in other flavors/manual bibitems).

3. **Date-type cascade lost — issued/circulated-only dates dropped.** (a) relaton-render base `date1` cascade: published → issued → circulated → first non-accessed, plus host-date fallback. (b) reference_transformer.rb:431 `extract_bibitem_date` accepts only `type == "published"`. (c) Input: `<bibitem><date type="issued"><on>2020-05</on></date>…` — empirically confirmed: new leg emits no `<date>`; old emitted `<date month="May" year="2020"/>`. Affects any non-IETF fetched reference whose relaton record carries issued/circulated rather than published. (d) Confidence: **high**.

4. **Refcontent reduced to a single identifier.** (a) config.yml standard template: `<refcontent>{{authoritative_identifier | join: ', '}}</refcontent>` over all eligible identifiers. (b) reference_transformer.rb:508 picks one id (ISO first, else first eligible). (c) Input: bibitem with ISO + IEEE docidentifiers — empirically confirmed: new refcontent is `ISO 2002` only; old rendered `ISO 2002, IEEE 802.2002`. (d) Confidence: **high** that behavior differs; **medium** severity.

5. **Formattedref precedence flipped when a title is also present — UNRESOLVED adjudication.** (a) references.rb `bibitem_render`: `if f || (!bib1.at(ns("./title")) && did)` — a formattedref wins over a co-present title (comment cites #279, BCP-collection items). (b) reference_transformer.rb:275 `formattedref_only?` routes to the formattedref path only when the title is absent/blank; with both present, the fetched title renders and the user-supplied formattedref is discarded (empirically confirmed: "User-Supplied Citation Text, 1999." lost, title kept, plus a refcontent the old path did not emit). (c) Caveat: in the new pipeline the presentation stage's shared bibrender may insert a formattedref into enriched bibitems, which may make the old precedence unportable wholesale — whether this flip is deliberate is **unresolved**; flag for adjudication rather than as a settled bug. (d) Confidence: **high** that output differs; adjudication open.

6. **Non-author/editor/publisher contributor fallback lost.** (a) origin/main:lib/relaton/render/parse.rb `creatornames_roles_allowed` (+ base cascade): translator, performer, adapter, distributor, authorizer render as authors when no author/editor exists. (b) reference_transformer.rb:400: author/editor, else publisher, else `Unknown`. (c) Input: bibitem whose only contributor is a translator — empirically confirmed: new emits `<author surname="Unknown"/>`, old emitted the translator. (d) Confidence: **high** that behavior differs; **medium** severity.

7. **References-section-level `<note>` → per-reference `<annotation>` lost.** Parse-ghosted by metanorma-document 0.2.9 (no accessor). Already **adjudicated as a model-vintage ledger item** in spec/feature/ref_spec.rb header ("re-test on 0.4.x") — reporting state, not a new gap. Also changed: bibitem-borne notes now render as annotations (old dropped them — adjudicated deviation), and multiple notes collapse into one space-joined `<annotation>` where old emitted one per note. (d) Confidence: high (spec-documented); severity capped by existing adjudication.

8. **formatted-initials loss (ledgered).** 0.2.9 parse ghost; surname + formatted-initials with no completename loses initials. Adjudicated in new ref_spec header (0.2.9 ledger). Already known.

9. **Refcontent over-emission for identifier types the old path excluded.** (a) old `authoritative_identifier_exclude`: ISSN/ISBN/DOI/URN/AUTHOR-DATE/TITLE/ISO-REFERENCE never reached refcontent. (b) `NON_REFCONTENT_TYPES` excludes only IETF family, DOI, metanorma types — an ISBN or URN docidentifier now becomes refcontent. (c) Input: `<docidentifier type="ISBN">…` with no other id. (d) Confidence: **medium** (code-read; over-emission, not loss).

10. **Prefatory non-bibitem elements inside references sections dropped.** Old parsed stray `p` into the references div (itself invalid v3). New drops silently. **Low** severity.

11. **Constituent anchor UUID fallback not ported.** Anchor-less referencegroup constituents may serialise `<reference>` with no anchor (RNG-invalid); constituent target now src-typed URIs only. **Low** (relaton STD/BCP constituents always carry IETF docids/src uris in practice).

12. **Keyword taxon/vocabid fallback unhandled.** vocab → bare text only; taxon-bearing keywords rare. **Low**.
