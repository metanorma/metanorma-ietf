## Findings

1. **Body/inline passthrough content dropped** — (a) rfc_convert.rb:103 `textcleanup` → isodoc base `passthrough_cleanup` (isodoc-3.7.1 lib/isodoc/function/cleanup.rb:8), fed by blocks.rb:10 `passthrough_parse` (format-gated, comma/space split per #275). (b) Old leg: `<passthrough formats="rfc">` content (AsciiDoc `pass:[]`, `++++` blocks) is entity-decoded and inserted raw into the RFC XML. The shared presentation layer retains `<passthrough formats=" rfc ">` elements (verified in isodoc-3.7.1 `passthrough1`), but the new leg's only passthrough consumer is reference_transformer.rb:66-110 (raw `<reference>` passthrough inside references sections); no section/block/inline transformer reads passthrough, so body passthroughs vanish. (c) Input: `++++\n<bcp14>MUST</bcp14>\n++++` or `pass-format:rfc[<br/>]` in body text — old emits the raw markup, new emits nothing. (d) Confidence: **high**.

2. **Invalid output no longer quarantined; downstream xml2rfc runs on it** — (a) rfc_convert.rb:107 `postprocess` + validation.rb:18 `content_validate`: on any content error, `FileUtils.mv(filename, "#{filename}.err")`, warn each error, warn "Cannot continue processing". (b) Old behaviour: no `.rfc.xml` is left on disk (only `.rfc.xml.err`), so `Processor#xml2rfc` (txt/pdf/html legs) cannot consume a known-broken file. New: processor.rb:77 `rfc_post_process` only warns; the invalid file is written normally and processor.rb:100 `xml2rfc` runs on it. The "Cannot continue processing" sentinel string, which downstream tooling/tests grep for, is also gone. (c) Input: any doc with `<<nonexistent-anchor>>` (xref target missing) — old yields `a.rfc.xml.err` and halts the chain; new yields `a.rfc.xml` plus xml2rfc's own failure or silently wrong text output. (d) Confidence: **high** (the `.err` convention is visibly load-bearing — the working tree is full of `*.rfc.xml.err` artefacts).

3. **Anchor NCName sanitisation no longer applied consistently to xref/eref targets** — (a) rfc_convert.rb:51 `populate_id` + :59 `to_ncname` (with the deliberate "do not sanitise `#`" split). (b) Old leg sanitised ids once on the input tree before xref resolution, so element ids and every rendered target string matched by construction, and `#`-carrying anchors survived intact. New leg applies base.rb:137 `to_ncname` (which replaces `#` and every other non-NCName char with `_`) to element anchors only, while inline_transformer.rb:209 emits `xref.target = target.to_s` raw. (c) Input: a user anchor that is not already an NCName, e.g. `[[terms and definitions]]` or an imported anchor `RFC5234#section-2` — the element serialises as `anchor="terms_and_definitions"` / `RFC5234_section-2` but xrefs to it keep the original string, producing a dangling IDREF (and a content_validate "target does not exist" warning that feeds Finding 2's non-halt). (d) Confidence: **medium** — depends on whether the presentation layer pre-normalises anchors before the model parse; the split `to_ncname` semantics for `#` are unambiguously not ported.

4. **Referencegroup members without id/docid get no anchor** — (a) cleanup.rb:44 `biblio_referencegroup_cleanup`: `e["anchor"] ||= "_#{UUIDTools::UUID.random_create}"`. (b) Old guaranteed every member `<reference>` an anchor (v3 requires anchor on reference). New transform_referencegroup (reference_transformer.rb:221) relies on `bibitem_anchor`'s IETF-docid fallback, and transform_constituent (reference_transformer.rb:250) sets anchor only `if constituent.id` — a constituent with neither id nor recognisable docid serialises `<reference>` with no anchor, which the RNG rejects. (c) Input: a `ref-included`/`relation type="includes"` group whose member bibitem lacks both an anchor and an RFC-shaped docidentifier (e.g. a STD umbrella citing a non-RFC member). (d) Confidence: **medium** (rare input shape, but the old code path defended it explicitly).

5. **Document annotations (cref) stubbed to nothing** — (a) cleanup.rb:7 `cleanup` calls `cref_cleanup(docxml)` (defined cleanup_inline.rb:64), and section assembly emitted crefs. (b) New: annotation_transformer.rb:20 `build_annotations` hard-returns `[]` (section_transformer.rb:170 loops over it), the `render_annotations?` gate is never consulted by any producer, and no transformer builds `Rfcxml::V3::Cref`; `cref`/`bookmark` cleanup passes are absent from cleanup_transformer.rb:41. (c) Input: an AsciiDoc reviewer comment with `:notedraftinprogress:` set — old emits `<cref>`, new emits nothing. (d) Confidence: **medium** (clearly a stub; corroborates A2/A3/A6 findings — CONSENSUS x4).

6. **Unknown-element fallback rendering lost (diagnostic surface)** — (a) rfc_convert.rb:83 `error_parse` else-branch: any unhandled element is emitted as escaped visible text in a `<t>`. (b) New leg: elements the model does not map are silently dropped during `from_xml`. Classified DROPPED-BY-DESIGN (the model architecture cannot reproduce it), but it changes failure mode from loud to silent: every future coverage gap becomes invisible in output rather than showing up as literal escaped XML. (c) Input: any presentation-XML element outside the model's vocabulary. (d) Confidence: high that the behavior is gone; low that it is a defect rather than an accepted architectural trade.

7. **Unparseable reference dates now fabricate a `year` from the first four characters** — (a) cleanup.rb:57 `biblio_date_cleanup` + front.rb:188 `date_attr`: non-ISO date text → `date_attr` returns nil → the `<date>` element is removed. (b) New: front_transformer.rb:322 else-branch `date.year = date_str[0, 4] if date_str.length >= 4` — arbitrary text yields a garbage year attribute (`"circa 2000"` → `year="circ"`); only fully empty parses are suppressed (reference_transformer.rb:453). (c) Input: a bibitem `<date type="published"><on>circa 2000</on></date>` — old emits no date, new emits `<date year="circ"/>`. (d) Confidence: **medium** (model-supplied `on=` values are usually ISO, but free-text dates are legal relaton). [Same mechanism as A1 Finding 7 — merge at synthesis.]

8. **refcontent cleanup skips the element after a deleted empty refcontent** — (a) cleanup.rb:78 `biblio_refcontent_cleanup` removed every empty `//refcontent`. (b) New cleanup_transformer.rb:369-382 calls `ref.refcontent.delete(rc)` inside `ref.refcontent.each` — Ruby's each-with-delete skips the successor element, so the second of two consecutive empty refcontents survives as an empty `<refcontent/>`. (c) Input: a reference whose rendering yields two adjacent empty refcontent entries (e.g. blank series + blank extent). (d) Confidence: **medium** on the mechanics (classic iteration bug), **low** on real-world frequency.

9. **Bare-ampersand escaping absent from the processor leg** — (a) transformer.rb:69 `escape_bare_ampersands` (the adjudicated F2 fix) runs in `convert_forward` (transformer.rb:51) *before* `u_cleanup`, whose comment states u_cleanup's Nokogiri parse "chokes on the bare entities". (b) The metanorma CLI path does not go through `convert_forward`: processor.rb:63 `document_transformers` serialises via core with the same `to_xml` options, then processor.rb:77 `rfc_post_process` — whose comment claims to "mirror convert_forward's serialisation tail" — calls only `Transformer.u_cleanup` and validation, never `escape_bare_ampersands`. The same F2 exposure therefore produces unparseable or entity-mangled RFC XML on the production CLI path while the library API is protected. (c) Input: any source text carrying a literal HTML entity reference (e.g. `&para;` in a paragraph) compiled via `metanorma -t ietf` rather than the Transformer API. (d) Confidence: **high** that the asymmetry exists; **medium** on end-to-end severity (depends on whether core's serialisation escapes those runs before post_process receives them).
