## Findings

1. **Review notes (cref) never emitted** — (a) `blocks.rb review_note_parse` + `render_annotations?`; (b) old emitted `<cref anchor= display= source= from=>` with name and content wherever a review/annotation appeared, gated on `render-document-annotations`/`notedraftinprogress`; (c) new leg: `lib/metanorma/ietf/transformer/annotation_transformer.rb:19-21` `build_annotations` returns `[]` (a stub), so an AsciiDoc `[reviewer=...]` review block / `cref:` annotation in a draft-in-progress document produces no `<cref>` at all — `section_transformer.rb:170` iterates an empty array; (d) confidence **high** (the gating predicate was faithfully ported, proving intent, but the builder is unimplemented).

2. **Body-level `<passthrough>` dropped** — (a) `blocks.rb passthrough_parse`; (b) emit raw content when `formats` (split on commas *and* whitespace — the #275 fix landed on this very branch's old leg) includes `rfc`; (c) a `pass:[]`/passthrough block or inline with `formats="rfc"` in any clause body: only `reference_transformer.rb:66-110` handles passthrough, and only inside references sections — nothing in `inline_transformer`, `section_transformer`, `block_transformer`, or the presentation layer touches it, so body passthrough content vanishes; (d) confidence **high**.

3. **Nested figures silently dropped** — (a) `cleanup_blocks.rb figure_unnest`; (b) old promoted `figure//figure` to top-level siblings, moving the parent's title in; (c) an AsciiDoc figure containing subfigures (`image::` twice under one `[[id]] .Caption ====` block): `figure_transformer.rb:32-59`'s element_order loop handles only `image`/`pre`/`sourcecode` tags, so nested `figure` children are neither unnested nor emitted; (d) confidence **high** (metanorma routinely produces subfigure markup).

4. **Sourcecode `src` attribute not carried** — (a) `blocks.rb sourcecode_parse` (`src: node["src"]`); (b) pass-through of external-source reference to `<sourcecode src="...">`; (c) presentation XML `<sourcecode src="file.c"/>`: `block_transformer.rb:355-407` never assigns `sourcecode.src` although `rfcxml-0.4.4 Sourcecode` maps it; output loses the src and, being contentless, emits an empty `<sourcecode/>`; (d) confidence **high** (attribute demonstrably supported on both sides, simply not wired).

5. **`keepWithPrevious` on paragraphs dropped** — (a) `blocks.rb para_attrs`; (b) `keep-with-previous` presentation attribute → `keepWithPrevious` on `<t>`; (c) `[keep-with-previous=true]` on an AsciiDoc paragraph: `transform_paragraph` (block_transformer.rb:37-60) sets only anchor/keepWithNext/indent; grep for `keep_with_previous` in lib/metanorma/ietf/transformer returns nothing, though `Rfcxml::V3::Text` maps it; (d) confidence **high**.

6. **Non-paragraph content dropped inside quote/admonition/note/example** — (a) `quote_parse`, `admonition_parse`, `note_parse`, `example_parse` all did `node.children.each { parse }` over every child; (b) full block nesting inside these containers; (c) concrete shapes: a blockquote containing a bullet list (`transform_quote` block_transformer.rb:431-434 walks paragraphs only, though v3 blockquote admits ul/ol/dl/sourcecode); an admonition containing a list or sourcecode (block_transformer.rb:464-467, paragraphs only); a note containing sourcecode/figure/table (block_transformer.rb:192-228 covers p/dl/ul/ol only); an example containing a note, quote or formula (EXAMPLE_CHILD_ATTRS block_transformer.rb:312-320 lacks them — the F7 fix added sourcecode/figure/lists/tables but not these three); (d) confidence **high** for quote/admonition lists (common authoring patterns), **medium** for note-with-figure and example-with-note.

7. **Figure key `<dl>` and intra-figure paragraphs dropped** — (a) `blocks.rb key_parse` + `cleanup_blocks.rb make_postamble/move_postamble/move_preamble`; (b) old rendered a figure's key dl and any pre/post-artwork paragraphs, then relocated them to siblings before/after the `<figure>`; (c) a metanorma figure with a key (`key:` dl after the image) or explanatory paragraph: `transform_figure` (figure_transformer.rb:32-59) has no `dl`/`p` branch — content vanishes; tables got the equivalent (`build_table_surroundings`, table_transformer.rb:155-175) but figures did not; (d) confidence **high** for the key dl, **medium** for paragraphs.

8. **`[SOURCE:]` emitted as in-figure `<postamble>`** — (a) `cleanup_blocks.rb move_postamble` (postambles always dissolved to siblings, so released output never contained `<postamble>`); (b) old guaranteed no v2-deprecated preamble/postamble elements in v3 output; (c) any figure with a source citation now serializes `<figure><postamble><t>[SOURCE: …]</t></postamble></figure>` (figure_transformer.rb:74-88) — `postamble` is deprecated/removed in RFC 7991 v3 prep-tool processing and may be rejected or stripped by xml2rfc; (d) confidence **medium** (depends on rfcxml serialization and xml2rfc tolerance).

9. **Clause-level `<pre>` (ascii-art outside figures) dropped** — (a) `blocks.rb pre_parse` (dispatched for any `pre`, not just in figures); (b) `<pre>` → `<artwork type="ascii-art">` wherever it occurs; (c) presentation-XML `pre` as a direct clause child (basicdoc allows it): `SRC_TO_RFC_TAG` (section_transformer.rb:248-264) has no "pre" entry and `parse_unordered_children` never reads a `pre` collection — the block is skipped; (d) confidence **medium** (depends on whether the ietf converter ever emits clause-level pre rather than figure/pre; the old dispatch handled it regardless).

10. **Leading-newline strip in artwork lost (#286 regression class)** — (a) `blocks.rb pre_parse`: `node.text.sub(/\A\n/, "")`; (b) exactly one leading newline removed before CDATA, deliberately `\A` not `^` to preserve interior blank lines; (c) `transform_pre_to_artwork` (figure_transformer.rb:187-198) does tab expansion and CDATA wrap but no leading-newline strip, so artwork whose model text begins with `\n` gains a spurious blank first line; (d) confidence **medium** (depends on whether the lutaml-model text mapping preserves the leading newline).

11. **Caption/name inline markup flattened to plain text** — (a) `figure_name_parse`, `example_label` (name children parsed recursively); (b) em/tt/xref inside figure/example captions rendered as inline elements in `<name>`; (c) `.Caption with *bold* or <<xref>>` on a figure: `ls_text` (figure_transformer.rb:21, block_transformer.rb:274) discards element structure, and an xref-only caption may collapse to empty; (d) confidence **medium** (text survives; markup and xrefs don't).

12. **Bookmark-derived dt/dd anchors lost** — (a) `cleanup_blocks.rb dt_cleanup/dd_cleanup` (`d["anchor"] ||= first bookmark's anchor`); (b) definition-list entries carrying `[[bookmark]]` anchors become linkable; (c) `[[anchor]]term:: definition` shapes: bookmarks are dropped outright in the new leg (block_transformer.rb:169-170 "not in RFC XML v3 schema"), and `dt_cleanup_single` (cleanup_transformer.rb:210-219) only recovers anchors from xrefs, so links targeting the bookmark dangle; (d) confidence **medium**.
