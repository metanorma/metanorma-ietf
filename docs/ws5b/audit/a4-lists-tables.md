## Findings

1. **li anchors lost.** (a) `origin/main:lib/isodoc/ietf/lists.rb:74-75` — `out.li **attr_code(anchor: node["id"])`. (b) Every list item's @id became `li/@anchor`; `transform_list_item` (lib/metanorma/ietf/transformer/list_transformer.rb:57-106) creates `Rfcxml::V3::Li` and never assigns `anchor`, although `ListItem` (metanorma-document 0.2.9 lists/list_item.rb:11) maps it. (c) `[[itemid]]` on a list item in AsciiDoc, then `<<itemid>>` — the xref will target an anchor that no longer exists in the RFC XML; xml2rfc errors on the dangling xref. (d) Confidence: **high**.

2. **Nested `dl` inside `li` silently dropped — dead guard.** (a) old lists.rb:74-83 parsed all li children generically. (b) list_transformer.rb:84-91 gates on `item.class.method_defined?(:definition_lists)`, but ListItem's attribute is `:dl` (list_item.rb:34); `definition_lists` exists only on clause models (cf. section_transformer.rb:483). The branch can never fire. (c) A definition list nested under a bullet/ordered list item (`*` item followed by `term:: def` with list continuation) vanishes from output. (d) Confidence: **high**.

3. **Block children of `li` dropped: figure, table, note, quote, example, formula.** (a) old lists.rb:74-83 (generic `parse`). (b) ListItem 0.2.9 carries all six accessors (list_item.rb:19-47); `transform_list_item` handles only text, p, ul, ol, (dead) dl, sourcecode. (c) An AsciiDoc list item containing an attached image/figure, admonition, blockquote, or table via `+` continuation loses that block entirely. (d) Confidence: **high** (model demonstrably carries the data).

4. **li child order not source order.** (a) old lists.rb:74-83 emitted children in document order. (b) `transform_list_item` appends all paragraphs, then all uls, then ols, then dls, then sourcecode — no `element_order` interleave, unlike `build_dd_ordered` (list_transformer.rb:256-280) which fixed exactly this class of bug for dd (WS5). (c) `* para1` + nested sublist + trailing continuation paragraph: the trailing `<t>` is serialized before the `<ul>`, reordering the author's prose. (d) Confidence: **medium-high** (depends on Li serialization honoring OrderTracker append sequence across mixed collections; dd needed the fix, li never got it).

5. **Header rows mixing `th` and `td` drop the `td` cells.** (a) old table.rb:38-45 — `node.elements.each … r.send td.name` preserved every cell with its own name and order in all sections. (b) table_transformer.rb:71-82: header role appends th cells; td cells are consulted only when there are NO th cells (and are then renamed th). A thead row with both (isodoc RNG permits td in thead tr) loses its td cells; there is also no element_order interleave for header rows. (c) Presentation XML `<thead><tr><th>A</th><td>B</td></tr></thead>` → `<tr><th>A</th></tr>`, cell B gone (also breaks column count). (d) Confidence: **medium** (construct is legal but uncommon from vanilla AsciiDoc tables).

   **5a. Block content inside table cells dropped.** (a) old table.rb:41-43 parsed all cell children generically, so lists, sourcecode, figures, nested tables in cells were emitted (v3 td/th legally contain ul/ol/dl/sourcecode/figure/table). (b) `transform_table_cell` (table_transformer.rb:121-153) handles paragraphs, interleaved inlines, and bare text only; TableCell 0.2.9 carries ul/ol/dl/figure/sourcecode/table/note/quote accessors (tables/table_cell.rb:46-73), all ignored — in the `element_order` path, `build_inline_element` returns nil for block tags, so they are skipped. (c) An AsciiDoc table cell with `a|` (AsciiDoc-content cell) containing a bullet list or listing block → cell emitted with the blocks missing. (d) Confidence: **high**.

6. **Table caption inline markup reduced to text.** (a) old table.rb:30-35 parsed `name` children (em, tt, xref inside caption). (b) table_transformer.rb:17-27 takes `ls_text` only — acknowledged in-code as metanorma-document 0.2.9 model gap (NameWithIdElement maps no inline collections). (c) `.Table of *important* values` → `<name>` loses the child element (text runs survive; an xref in a caption disappears wholesale). (d) Confidence: **high** that behavior differs; already documented as WS3 model gap — report tracks it as an open PARTIAL, not new.

7. **table @align not ported.** (a) old table.rb:4-6 `attr_code(anchor:…, align: node["align"])`. (b) TableBlock 0.2.9 maps `align` (tables/table_block.rb:63,88) and rfcxml 0.4.4 `Table` has an `align` attribute, but `transform_table` never copies it; rfcxml's default `"center"` may additionally force `align="center"` on tables that had none. (c) Presentation XML `<table align="left">` → alignment lost (or overridden to center). (d) Confidence: **medium** (depends on the ietf presentation layer actually emitting table/@align; old code deliberately read it).

8. **Notes attached inside dl/ul/ol dropped.** (a) old lists.rb:53 `dl_parse_notes` (isodoc-3.6.x function/lists.rb:114-117: all non-dt/dd, non-fmt-name dl children parsed after the dl) and old ul/ol_parse's generic child walk (lists.rb:10-14, 35-39) — the RNG allows `note` after list items. (b) New transformers iterate only dt/dd (dl) and listitem (ul/ol); the 0.2.9 DlElement/UnorderedList/OrderedList models expose no note accessor, so this is model-ghosted as well. (c) `note::` inside a definition list block → the old `<aside>` after the `</dl>` no longer appears. (d) Confidence: **medium** (gap is real; frequency low, and fixing requires a model addition).

9. **dt inline coverage incomplete: link, stem, br, fn.** (a) old lists.rb:56-63 delegated element dt children to the generic parser (links, stems, footnotes, br all emitted). (b) `build_dt_inline` (list_transformer.rb:191-207) handles simple inlines + xref/eref only; DtElement 0.2.9 maps link, stem/fmt_stem, br, fn, strike, underline — in the interleave those tags return nil and their content is omitted from `dt`. (c) `http://example.com[site]:: definition` — the hyperlink text vanishes from the emitted `<dt>`. (d) Confidence: **medium-high** for link/stem (content loss); fn arguably RELOCATED with the footnote-enrichment drop.

10. **dd block coverage incomplete: note, quote, example, formula.** (a) old lists.rb:69-71 parsed every dd child. (b) DD_CHILD_MAP (list_transformer.rb:241-248) covers p/ul/ol/dl/sourcecode/table (+figure specially); DdElement 0.2.9 also maps note, quote, example, formula — unhandled in both `build_dd_ordered` (tag not in map → skipped) and `build_dd_unordered`. (c) `term::` followed by an attached NOTE admonition or blockquote in the definition → block dropped. (d) Confidence: **medium-high**.

11. **ol unknown non-% type collapsed to "1".** (a) old lists.rb:24-26 `OL_STYLE[type&.to_sym] || type` — any unrecognized type string passed through verbatim. (b) `map_ol_type` (list_transformer.rb:351-365) preserves the F3 %-format strings (verified in place) but sends every other unknown value — including already-literal v3 types "a"/"i"/"A"/"I"/"1" — to `"1"`. (c) Presentation XML `<ol type="a">` (literal, not "alphabet") → `type="1"`, renumbering the list style. (d) Confidence: **low-medium** (standoc normally emits the spelled-out keywords; literal values would come from hand-authored or foreign presentation XML).

12. **Checkbox rendering for (un)checkedcheckbox li dropped.** (a) old lists.rb:74-83 injected `<span class="zzMoveToFollowing"><input type="checkbox"…/></span>` (with the checked-state inverted — an old-leg bug). (b) New leg ignores the attributes although ListItem maps them (list_item.rb:49-50). (c) `- [ ] item` checklist syntax → no checkbox marker at all. (d) Confidence: **low** as a genuine regression — the old output was invalid RFC XML v3 (`span`/`input` are not v3 vocabulary) and would have failed xml2rfc; plausibly DROPPED-BY-DESIGN, but no in-code note says so.

13. **dl title (fmt-name) dropped.** (a) old lists.rb:47 via inherited `list_title_parse` (isodoc function/lists.rb:4-9) emitted `<p class="ListTitle">` before the dl. (b) New `transform_definition_list` ignores DlElement's `name`/`fmt_name`. (c) `.Title` on a deflist → title gone. (d) Confidence: **low** — the old emission (`p` with an HTML class) is itself invalid v3, so the old behavior was already broken for this output format; flagged for completeness.
